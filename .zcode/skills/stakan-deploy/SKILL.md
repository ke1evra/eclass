# Выпуск через Stakan

Откройте [Деплои](https://stakan.script-setup.ru/deployments) и выберите проект **ECLASS**. Проверяйте включённое окружение, ветку, обязательные проверки и режим публикации. Обычный путь: MR → слияние → серверные проверки точного итогового SHA → публикация проверенного артефакта → проверка доступности.

Приложение работает через systemd. Выпуск переключает каталог проверенного артефакта через current; прежний EnvironmentFile и отдельная MongoDB сохраняются. Проверки используют временную replica set и тестовые данные, а не рабочую базу.

GitHub Actions не являются обязательным звеном этого выпуска. Старые инструкции про прямой push/deploy workflow или сборку рабочего каталога не запускать параллельно новому правилу. Операторские сценарии, SSH-подключение и профили установлены отдельно от кода проекта; обычный релиз их не переписывает.

Сборки на общем сервере выполняются последовательно. Проверки работают в изолированных контейнерах с временной базой, без производственных env и Docker socket. Перед переключением обязателен проверенный бэкап. Неуспешная публикация возвращает предыдущую версию приложения; восстановление базы не является автоматическим откатом.

Если окружение требует подтверждения, кнопка публикации относится к отображаемому SHA. Изменившаяся ветка или настройка требует новой проверки. Не обходить это включением автоматического режима без запроса пользователя.

При ошибке смотрите этапы сборки и ход джобы в Stakan. Сначала сверяйте точный SHA, результат проверок и реально работающую версию; после неопределённого результата не повторяйте выкатку вслепую. Не освобождайте место за счёт чужого кэша, образов, томов, рабочих файлов или бэкапов.

В задаче сохраните MR, результаты проверок, журнал выкатки, подтверждение работающей версии и скриншоты. Секреты и закрытые серверные отчёты не публикуйте в репозитории.
