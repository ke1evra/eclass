# Jobs-to-be-Done и 5 главных потребностей — MVP

Каждая фича MVP обязана трассироваться хотя бы до одной потребности из списка
ниже (соответствие проверяется тестом `metrics/contract.test.ts`:
`USER_NEEDS` содержит ровно 5 записей, у каждой есть `mvpFeatures`).

| # | Потребность (с точки зрения пользователя) | MVP-фичи, закрывающие её |
|---|-------------------------------------------|--------------------------|
| 1 | Я хочу быть уверен, что задание совпадает со структурой и содержанием **актуального экзамена ФИПИ**. | versioned-question-bank, editorial-import, fipi-golden-set |
| 2 | Я хочу пригласить ученика **одной ссылкой** без путаницы с регистрацией и дублированием классов. | invite-by-code-or-link, self-service-class |
| 3 | Я хочу выдать **конкретную работу конкретному ученику/группе** с понятным сроком. | assignment-builder, recipient-targeting, deadlines |
| 4 | Ученик должен **сдать работу с телефона без потери ответа** даже при кратковременном разрыве сети. | autosave, idempotent-submit, offline-resume, pwa-shell |
| 5 | Я хочу дать **объясняющую обратную связь** и увидеть, что ошибка отработана, а не просто поставить балл. | rubric-review, feedback-thread, remediation-loop |

## JTBD утверждения

- **Учитель:** «Когда у моего ученика есть пробел по теме — я хочу быстро
  диагностировать его, назначить индивидуальную работу и получить понятный
  разбор, чтобы он реально вырос, а не просто получил оценку.»
- **Ученик:** «Когда мне задали работу — я хочу понять ближайший шаг, спокойно
  сдать с телефона без страха потерять ответ и получить разбор, чтобы в
  следующий раз не ошибиться там же.»

## Главный продуктовый цикл

```
учитель создаёт класс
  → приглашает ученика (код/ссылка)
    → собирает/назначает работу
      → ученик выполняет и сдаёт (autosave + идемпотентная отправка)
        → система проверяет закрытые ответы
          → учитель проверяет развёрнутые по рубрике ФИПИ
            → ученик получает feedback и работу над ошибками
              → команда измеряет, исправлена ли ошибка (метрики)
```

Этот цикл — основа acceptance-теста `tests/acceptance/critical-flow.spec.ts`
и критического E2E в воркфлоу TDD.
