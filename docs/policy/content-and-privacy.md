# Политика контента и персональных данных — ECLASS-12

> Канон:
> `src/domain/content-policy.ts` (publish gate + PII redaction),
> `src/domain/retention.ts` (retention windows + deletion flow).
> Этот документ — человеческая проекция; при расхождении важнее код.

## 1. Sourcing контента

Допустимые источники (перечислены в `CONTENT_SOURCES`):

| Kind | Что это | Требования |
|---|---|---|
| `fipi` | Материалы ФИПИ-2026 (банк, демоверсии, кодификаторы, спецификации) | `ref` — стабильный id в источнике; `url` желателен |
| `authored` | Оригинальные материалы команды/учителя | **обязателен** `license` (доказательство прав на публикацию) |

**Запрещено:** любой другой источник (`copied`, `unknown` и т.п.). Каноническая
структура экзамена — ФИПИ (ADR-0003).

## 2. Редакционный publish gate

`canPublishQuestion(draft)` — единственный способ опубликовать задание.
Возвращает отказ с причиной, если не выполнено **любое** из:

- есть непустой `subjectVersionId` (привязка к версии предмета/учебного года);
- есть `source`, и его `kind` входит в `CONTENT_SOURCES`;
- для `authored` — есть `license`;
- `editorStatus === 'reviewed'` (редактор подтвердил корректность).

Это программный ответ на боль «ошибки в заданиях», зафиксированную в
исследовании по ЯКлассу: задание без источника и версии **не может** быть
опубликовано.

## 3. PII redaction — единая точка для логов

`redactPii(input)` — чистая детерминированная функция, через которую проходит
**любая** строка перед попаданием в лог/аудит:

- email → `[redacted:email]`
- российские телефоны → `[redacted:phone]`
- длинные цитаты (>40 символов в кавычках) → `[redacted:answer]` — эвристика
  против случайного копирования текста ответа в лог.

Структурно PII вообще не должны попадать в события: `AuditEvent`-контракт
(ECLASS-10) не содержит полей `email`/`name`/`answerText`. Redaction — вторая
линия обороны на случай ошибки в коде.

## 4. Retention (сроки хранения)

| Категория | Дней | Действие | Причина |
|---|---|---|---|
| `answer_text` | 365 | anonymize | учебная ценность в течение года, далее — агрегаты |
| `audit_log` | 730 | keep | безопасность и расследование инцидентов (дольше ответов) |
| `telemetry` | 90 | delete | только агрегаты без PII |
| `account_metadata` | до удаления | anonymize | живёт с аккаунтом до запроса на удаление |

Принцип: **минимизация**. Хранится ровно столько, сколько нужно для обучения и
комплаенса; ничего «на всякий случай».

## 5. Удаление аккаунта (152-ФЗ)

`planAccountDeletion(accountId, requestedAt)` формирует auditable-план:

1. **Немедленно (0 дней):** `revoke_sessions` — отзыв активных сессий.
2. **После grace-периода (30 дней):**
   - `answer_text` → anonymize;
   - `telemetry` → delete;
   - `account_metadata` → anonymize.
3. **Audit log НЕ удаляется** — сохраняется по собственной политике для
   безопасности. Это явно задокументированный шаг.

Grace-период 30 дней даёт пользователю окно для отмены в случае ошибки.

## 6. Возрастной контур и согласия

- Целевая аудитория — 9–11 классы (несовершеннолетние). Обработка ПДн — по
  принципу минимизации (NFR).
- Согласие на обработку и возрастной контур фиксируются при регистрации
  (процедура будет формализована в P1, `ECLASS-13`).
- Чувствительные данные не попадают в логи и продуктовую аналитику (раздел 3 +
  контракт `AuditEvent`).

## 7. Владелец процесса ежегодного обновления

- Ежегодное обновление демоверсий/кодификаторов ФИПИ — ответственность
  **редактора контента** (персона из `docs/product/personas.md`).
- Процедура: импорт новой версии → редакторская валидация → публикация через
  `canPublishQuestion`. Операционный кабинет — `ECLASS-40`.

## Соответствие критериям приёмки ECLASS-12

- ✅ Задание без источника и версии нельзя опубликовать (`canPublishQuestion`
  + 12 unit-тестов).
- ✅ PII и тексты развёрнутых ответов отсутствуют в технических логах
  (`redactPii` + тесты на email/phone/answer/structured event).
- ✅ Есть владелец процесса ежегодного обновления (редактор контента,
  операционный контур в `ECLASS-40`).
